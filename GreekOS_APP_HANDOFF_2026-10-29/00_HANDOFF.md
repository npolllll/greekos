## 3. Как было начато: воспроизводимая проверка импорта и контрактов

1. `TOOLS/verify_archive.py` для исходного ZIP → CRC и SHA-256 манифеста PASS, 4271 запись.
2. `TOOLS/verify_handoff.py` (Python 3.12, зависимости из `TOOLS/requirements.txt`) → **PASS, 19 366 проверок**,
   0 ошибок; инвентарь совпал с `LIVE_INVENTORY.json`.
3. Собственный импортёр приложения повторяет и расширяет эти проверки — **22 886 проверок**: JSON Schema
   каждого задания, SHA-256 и побайтное равенство `original_payload` каноническому файлу, FK (уроки,
   компетенции, источники, аудио, рубрики, тексты), DAG предпосылок, хеши экзаменов, ровно 15 компонентов,
   1031 неразрешённый тег остаётся `null`, 42 обоснованных решения по тегам сохранены.
4. Импорт выполняется одной транзакцией в порядке `CONTRACTS/IMPLEMENTATION.json#import.order`; повтор с тем
   же хешем — без изменений; новый хеш — новая неизменяемая ревизия, отзыв старых допусков, инвалидация аудио.

## 5. База данных и безопасность

- **Миграции** (`app/supabase/migrations`, 9 шт.): `…0001_content_schema` (контент, ревизии, допуски, политики,
  аудио, библиотека контекста), `…0002_learner_schema` (профили, роли, ученические данные, события, согласия,
  речь, экзамены, аудит), `…0003_security_rls` (RLS, гранты, бакеты, Realtime), `…0004_commit_functions`
  (атомарная идемпотентная запись), `…0201_exams` (усиление проверки владельца строк), `…0301_synthetic_guards`,
  **v5.4:** `…0401_voice_audio_v54` (каталог голосов, роли и кастинг, статусы аудиозаданий, мастер/нормализация/
  история у аудио, метрики реплик), `…0402_voice_stream` (услышанная часть прерванной реплики),
  `…0403_exam_audio_plays` (серверный счёт прослушиваний экзамена).
- **Модель доступа:** `anon` — ничего; ученик — только SELECT своих строк при активном профиле; вся запись —
  сервер (service role) после проверки сессии через Auth-сервер; роль `owner_admin` — в защищённой таблице;
  деактивация = бан + отзыв сессий + RLS по `profiles.active`.
- **Голосовой шлюз:** короткоживущий HMAC-токен (60 с, одноразовый, привязан к пользователю и сессии),
  проверка Origin, ключи провайдеров только на сервере/шлюзе, лимит объёма аудио, сырой голос не хранится.
- **Хранилище:** 3 приватных бакета (`course-audio`, `tts-cache`, `voice-review`), доступ только по коротким
  подписанным ссылкам после серверной проверки.
- Подробности: `database/README_DATABASE.md`, `database/SCHEMA_REFERENCE.md`.

## 6. Ключевые технические решения (и почему)

| Решение | Причина |
|---|---|
| Запись учебных фактов через одну SQL-функцию с пакетом JSON | атомарность + идемпотентность + сериализация по ученику; клиент не может записать оценку |
| Хеш задания = SHA-256 канонизированного envelope (не только файла) | смена ключа/политики оценивания тоже инвалидирует допуск |
| Отличие только в ударении → `INCORRECT_CONFIRMED`, `meaning_changing=false` | `strip_accents=false` в политике заданий; не считается смысловой ошибкой для 80/20 |
| Отличие только в типографике/пунктуации → `ACCEPTABLE_VARIANT` | смысл и форма совпадают; не штрафовать за кавычки/апостроф |
| `REVIEW_REQUIRED`-задания с ключом — обратная связь есть, но `reliable=false` | стратегия корпуса требует проверки; mastery только после AI (high) или человека |
| Диагностика: старт маршрута не выше B1 | пробы заканчиваются на B1; «B2 по трём вопросам» запрещено спецификацией |
| `requires_audio` без аудиозаданий = задание на говорение ученика | так размечены устные пробы диагностики; иначе они навсегда закрылись бы «ожиданием аудио» |
| Модель Claude по умолчанию `claude-opus-5-5` (переопределяется env) | текущая модель; структурированный вывод + серверный fallback при отказе |
| Голос ученика → WAV 16 кГц в браузере | единый формат для OpenAI и Azure, реальный индикатор уровня, ничего не хранится без согласия |

## 7. Найденные несоответствия в исходном пакете (исправлены в коде приложения, корпус не менялся)

1. Аудиозадания используют два формата сегментов: курс — `segment_id/speaker_role/text_el`, экзамены
   L01–L03 — `cue_id/speaker/text`. Пайплайн нормализует оба.
2. `priority` в аудиозаданиях не всегда число (например `CORE_AFTER_L01`) — хранится как текст.
3. Идентификаторы пакетов ΠΕΓΠ лежат в разных полях (`batch_id`, `packet_id`, `pack_id`, у P01 — `module_id`) —
   используется имя файла.
4. 4 разговорных сценария Real Greek (`GreekOS_Real_Greek/speaking/RG-S01…04`) отсутствуют в
   `HANDOFF_IMPORT/speaking_scenarios.json` — импортируются отдельно, помечены «без оценки».
5. Устные пробы диагностики (`D-*-SPOKEN_*`, `D-*-PRONUNCIATION`) имеют `requires_audio=true` без
   аудиозаданий — трактуются как требование речи ученика (см. §6).
6. 10 заданий основного курса не входят ни в одну секцию урока — показываются в «Практике».

## 9. Что делать дальше (у вас есть ключи)

1. Локально: `cd app && npm ci && npx supabase start`, `.env.local` по `.env.example` (+ ключи, `VOICE_GATEWAY_SECRET`),
   БД способом A или B из `database/README_DATABASE.md`, `npm run owner:create -- --email <e-mail> --name "<Имя>"`,
   `npm run dev`, при живом разговоре — `npm run voice:gateway`.
2. Админ → Провайдеры → «Проверить подключение» (Claude, ASR, TTS).
3. Админ → Голоса и кастинг: обновить каталог, прослушать образцы, утвердить голоса (женский и мужской),
   назначить роли, откастовать персонажей с именами; `npm run audio -- render-batch --budget-cap N`;
   `npm run audio -- report`; записать права провайдера.
4. Замерить живой разговор с облачными движками: `npm run voice:bench`, затем вручную на телефоне.
5. Тесты: `npm test`, `npm run test:integration`, `npm run test:e2e` (только против локального стека; живой
   E2E требует шлюз и распознавание).
6. Решить вопрос публикации (внешняя проверка или подписанная цифровая политика), затем облако по `DEPLOYMENT.md`.
