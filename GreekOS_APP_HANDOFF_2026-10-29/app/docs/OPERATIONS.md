# Эксплуатация

## Выпуск материалов ученикам

1. **Политика.** Админ → Политика выпуска. Цифровой выпуск без внешней экспертизы возможен только
   после подписи `DIGITAL_ONLY_RISK_ACCEPTED` с явным признанием рисков. Ученик видит у таких
   уроков метку «Цифровая проверка, без независимой экспертизы». Отзыв политики отзывает все
   выпущенные по ней допуски.
2. **Внешняя проверка.** Если урок проверил преподаватель/экзаменатор, выпуск оформляется как
   `HUMAN_TEACHER_REVIEW` / `HUMAN_EXAMINER_REVIEW` со ссылкой на файл доказательства и его SHA-256.
   Система сама никогда не ставит `HUMAN_*`.
3. **Выпуск.** Админ → Контент и QA → урок → «Выпустить урок» (урок + его задания на текущий хеш).
   Задания с аудио остаются закрытыми до выпуска проверенного аудио. ΠΕΓΠ выпускается только с
   датой окончания (на конкретную экзаменационную сессию).
4. **Изменение корпуса.** Повторный импорт: тот же хеш — без изменений; новый хеш — новая ревизия,
   старые допуски отзываются (`CONTENT_HASH_CHANGED`), аудио инвалидируется
   (`SCRIPT_HASH_CHANGED`). История попыток не переписывается.

## Аудио (только цифровой синтез)

```bash
npm run audio -- validate                         # хеши сценариев против корпуса, без сети
npm run audio -- plan --ids U-A1-001-AUD01         # голоса по ролям, сегменты, оценка стоимости, plan_hash
npm run audio -- render --ids U-A1-001-AUD01 --approved-plan-hash <hash> --budget-cap 2
npm run audio -- inspect --audio-id U-A1-001-AUD01 # повторный технический анализ файла
```
Или Админ → Аудио. Статусы: `TECHNICAL_PASS/FAIL` (декодирование, длительность, энергия, клиппинг,
тишина, паузы — профиль `greekos-tts-technical/1`), ASR round-trip (WER ≤ 0.25, CER ≤ 0.12, ударения),
итог `AUDIO_VERIFIED_DIGITAL` или `NEEDS_REVIEW`. Далее: записать условия провайдера (права) →
выпустить аудио. Сомнительные интонации Real Greek не выпускаются как образец живой речи.

v5.4 — кастинг и статусы задания: `AUDIO_PENDING → GENERATED → TECH_QA_PASS/FAIL →
LINGUISTIC_QA_PENDING → DIGITAL_REVIEWED → RELEASE_ELIGIBLE` (последний — только при утверждённом
кастинге, записанных правах и цифровой проверке; это ограничение стоит и в БД). Задание без
утверждённого голоса нужного пола — `BLOCKED_NO_SUITABLE_VOICE`, без кастинга персонажей —
`BLOCKED_MISSING_VOICE_METADATA`; молча не пропускается и не озвучивается «похожим» голосом.
У каждого файла хранятся мастер-версия, нормализованная копия (−20 dBFS RMS, пик ≤ −1 dBFS),
измеренные таймкоды сегментов, параметры генерации, хеши и история перегенерации. QA дополнительно
помечает возможный обрыв конца сегмента, подозрительный темп и пропуски/повторы слов (сигналы для
разбора, не вердикт).

```bash
npm run audio -- cast                              # каталог голосов + предложения кастинга
npm run audio -- render-batch --budget-cap 0        # всё, для чего есть утверждённый/подходящий голос
npm run audio -- report --out reports/v5.4          # AUDIO_RENDER_REPORT.json + VOICE_CATALOG.json
npm run audio:benchmark                            # 30 фраз × голоса × скорости, ASR round-trip
```

## Живой разговор (голосовой шлюз)

```bash
npm run local:asr       # локальная разработка: Whisper small/medium на 127.0.0.1:3312
npm run voice:gateway   # WebSocket-шлюз на 127.0.0.1:3311 (в облаке — отдельный сервис, см. DEPLOYMENT)
npm run voice:bench     # замер задержек и ASR на синтетических клипах через настоящий шлюз
```
Метрики каждой реплики пишутся в `speaking_turn_metrics` (VAD, ASR final, диалог, первый звук TTS,
фактический старт воспроизведения, прерывания); синтетические прогоны помечены
`synthetic_test_clip`. Сырой голос шлюз не хранит — только подтверждённый текст реплик.

## Мониторинг

- `GET /api/health` — доступность БД (для uptime-монитора).
- Vercel → Logs / Observability: ошибки обработчиков (`[route-error]`), длительность функций.
- Админ → Провайдеры: расход за сутки/месяц по `provider_usage`, последние проверки подключения.
- Supabase → Reports / Logs: Auth, Realtime, Postgres.
- Админ → Голоса и кастинг: p50/p95 задержек живого разговора по источнику речи; `GET <шлюз>/health`.
  Пороги SLO подтверждаются пилотом на реальных устройствах и сетях.

## Лимиты расходов

`BUDGET_DAILY_USD_PER_USER` и `BUDGET_MONTHLY_USD` блокируют вызовы LLM/ASR/TTS при превышении
(ответ 429 с понятным сообщением; учебные данные не теряются). `AUDIO_RUN_BUDGET_USD` ограничивает
одну генерацию аудио. Дополнительно задайте лимиты в консолях провайдеров.

## Резервные копии и восстановление

- Supabase: ежедневные бэкапы (план Pro) или PITR. Регулярно скачивайте логический дамп:
  `npx supabase db dump --linked -f backup.sql` (+ `--data-only` для данных).
- Корпус воспроизводим: любой экземпляр восстанавливается миграциями + `npm run import` из
  исходного пакета (хеши проверяются).
- Storage: `course-audio` воспроизводим из пайплайна; `voice-review` не бэкапится (по политике
  хранится ≤ 30 дней).

## Откат

- Приложение: Vercel → Deployments → Instant Rollback на предыдущую сборку.
- Миграции — только вперёд. Для отката схемы пишется компенсирующая миграция; перед применением
  новой миграции в production сделайте `db dump`.
- Ошибочный выпуск материала: Админ → отозвать допуск (запись остаётся в журнале, попытки учеников
  сохраняются).

## Данные учеников

- Экспорт: ученик — Настройки → «Скачать все мои данные»; владелец — карточка ученика → Экспорт.
- Удаление: ученик сам (ввод «УДАЛИТЬ») или владелец; удаляются записи голоса, сессии и все строки
  ученика (каскад), остаётся только обезличенная запись в журнале аудита.
- Деактивация: блокирует вход и API сразу (бан + отзыв сессий + RLS по `profiles.active`).
- Голос: по умолчанию не хранится; с согласием — до 30 дней; отзыв согласия удаляет записи сразу,
  ежедневный cron удаляет просроченные.

## Инциденты

1. Утечка ключа провайдера: отозвать ключ в консоли провайдера → заменить в Vercel → redeploy.
2. Утечка `service_role`: Supabase → API → rotate secret → обновить Vercel → redeploy.
3. Ошибка оценивания: отозвать допуск затронутых заданий; оспаривания учеников и ручная проверка
   владельцем добавляют компенсирующие события без переписывания истории.
