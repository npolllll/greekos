# Статус GreekOS — 03.11.2026 (v7: завершение локального продукта)

Продолжение v6.1 в той же ветке. Всё проверено в работающем приложении в локальной среде (Linux, 4 CPU,
без GPU, Supabase в Docker). Облако, платные AI и ключи не подключались. Как принять сборку на своей
машине — [ACCEPTANCE.md](ACCEPTANCE.md).

## 1. AI-разговор: задержка и естественность

- **Найдена настоящая причина «дефекта KV-кэша Gemma»**, из-за которого в v6.1 кэш был выключен:
  сервер передавал прошлое окно контекста в `lastEvaluationContextWindow`, и node-llama-cpp брал это
  старое окно вместо новой истории — модель отвечала на прошлый ход. Без этого параметра ответ с
  кэшем совпадает с чистым пересчётом (проверено); переиспользование включено для всех моделей.
- **Прогрев до слов ученика**: пока персонаж говорит и ученик отвечает, сервер вычисляет следующий
  промпт (этапы сцены, факты) до места, куда встанут слова ученика; ход обрабатывает только их.
- **Планирование на сервере модели**: у каждого разговора свой слот, слоты работают параллельно;
  ход ученика прерывает прогрев своего слота и не ждёт разбор фразы. Прогрев и разбор начинаются
  после синтеза речи ответа, а не во время него. Потоков — все ядра, кроме одного (генерация
  упирается в память; свободное ядро — синтезу речи).
- Короткая первая реакция персонажа («Εντάξει.», «Ωραία.») звучит сразу.
- **Apple Silicon**: Metal + flash attention по умолчанию, CoreML для Whisper, MPS для Coqui;
  `npm run local:doctor` показывает, что реально включено, `npm run speaking:latency` измеряет.

| Задержка AI-собеседника (CPU 4 ядра, после распознавания) | v6.1 | v7 |
|---|---|---|
| Первый токен модели | 5–10 с | **0,27–0,40 с** (690–765 из ~750 токенов из кэша) |
| Первое проверенное предложение | p50 10,3 с | **1,6–3,9 с** |
| Ход целиком | 12,6 с | 6–8 с |

Цель пилота (конец речи → звук ≤ 1,5 с) на этом CPU не достигнута: распознавание Whisper small
≈ 2–7 с, синтез первого предложения ≈ 1 с. На Mac с Metal/CoreML — измерить `speaking:latency`.

## 2. AI-разговор: педагогическая точность исправлений

- **Правила курса** (`src/lib/speaking/grammar-rules.ts`): σε + артикль, να после πρέπει/θέλω/μπορώ,
  лицо глагола после εγώ/εσύ, множественное число после числа, (σ)τον + мужской род, согласование
  числительных (с различением «ένα καφέ» = кафе и «έναν καφέ» = кофе по контексту). Формы
  подтверждаются словарём; ученик видит пометку «Правило курса (проверка без AI)». Те же правила
  исправляют реплики персонажа до озвучки.
- **Проверка правил на корпусе** (`npm run rules:corpus`): первая версия дала 34 ложных срабатывания
  на 6 623 выверенных предложениях (кафе, «τέσσερις παρά τέταρτο», «επτά στο πάρκο»); после
  исправлений — **0**. Те же ложные срабатывания были в старом правиле числительных v6.1 — исправлены.
- Исправление модели отбрасывается, если фраза дословно есть в выверенном греческом курса или если
  само исправление нарушает правило.

Набор `speaking:eval` v2 (34 случая, +9 на исправления), Gemma 4 E2B:

## 3. Аудио: техническая обработка 142 заданий

- **14 диалогов озвучивались одним голосом, который читал метки ролей** («Πελάτης: … Υπάλληλος: …») —
  а проверка распознаванием это пропускала, потому что метки были и в эталоне. Сценарии с метками
  теперь разбиваются на реплики говорящих: каждому — свой голос по кастингу, метки не звучат.
  Файлы, озвученные «не теми говорящими», снимаются автоматически (`SCRIPT_SPEAKERS_CHANGED`).
- Проверка распознаванием понимает время «6:30» = «έξι και μισή» и намеренно повторённые фразы
  диктантов (Whisper склеивает повтор).
- Мужской голос MBROLA: замер разборчивости на 40 мужских репликах — 48–53% ошибок по словам при
  любых скорости/паузах; лучший вариант конвейер уже применяет при перегенерации.
- Новые открытые греческие голоса: Hugging Face и серверы Meta (MMS) закрыты политикой сети; все
  доступные открытые голоса — та же дикторша CSS10.
